## Why

Lock the desktop, walk away, come back hours later, move the mouse — the TV stays dark. `tisvlay-session`'s `on_session_unlock = screen_on` dispatched the LG `turnOnScreen` command and the LG client returned `Ok`, but the panel never came on. Root cause was a one-two: the LG client masked every `TvError` as idempotent-success (swallowing the `-102 not in screen-off substate` signal), and `PowerState::ActiveStandby` was mis-mapped to `is_screen_on = true` so the cached `Tv1.Power.PowerState` property read `"active"` while the panel was dark. Without a verify-and-escalate path, the session service had no way to notice and recover.

This PR adds an Action QoS feature — a per-event `qos.reliability` field on profile slots — and a reliable-tier dispatcher that verifies post-action state and escalates to `power_on` with WoL when a `screen_on` doesn't actually wake the panel. Along the way it fixes both of the bugs above (a regression test would have caught either, neither would have caught both together).

## What ships

**Per-event QoS namespace in profile config** ([docs/design.md](docs/design.md#action-qos-reliability) "Action QoS (Reliability)" for the resolve chain and config examples). Each `on_*` slot grows from `Option<SessionAction>` to a `{ action, qos }` table; the `qos` namespace currently carries one dimension — `reliability: best_effort | reliable` — with room for `deadline` / `durability` siblings later without schema break. The asymmetric default is type-driven via `default_reliability_for(action)`: wake-side actions default to `reliable`, sleep-side to `best_effort`. Profile merge recurses through each leaf so `qos.reliability` can be overridden independently of `action` at any tier in the resolution chain.

**Single `Tv1.Dispatch(action, qos)` D-Bus entry point** for lifecycle actions. Replaces `Tv1.Power.PowerOn` / `Tv1.Power.PowerOff` / `Tv1.Screen.SetScreen` — those are gone. `action` is the snake-case form of `SessionAction` (`"screen_on"`, `"screen_off"`, `"power_on"`, `"power_off"`, `"none"`); `qos` is a JSON `QosConfig` object (e.g. `{"reliability":"reliable"}`, `{}` for the action-derived asymmetric default). Direct callers use `DaemonClient::{screen_on,screen_off,power_on,power_off}` one-liner wrappers that pass best-effort QoS. Session and system events route through here with the per-event resolved reliability tier.

**Daemon-side reliable dispatch tier** in `tv_manager::dispatch_reliable_screen_on`. The session crate's `execute_action_for_tv` is now a one-liner that forwards `(action, qos)` to `daemon.dispatch_action`; the daemon owns the verify-retry-escalate state machine. Two pre-flight short-circuit predicates head the helper: (a) cached `last_known_power_state == "standby"` (the daemon's derived shorthand for `is_on == false`) skips `screen_on` and dispatches `power_on` directly — the TV is past Screen Off, `screen_on` would either no-op or stall the LG client's `REQUEST_MS`; (b) the QoS-aware dedup carve-out in the session lib ensures Reliable bypasses the `last_action` cache, since the whole point of the reliable tier is verifying the TV actually reached the target state. For `(ScreenOn, Reliable)` past the short-circuits it: sends `screen_on`, waits 300 ms for the backend's power-state subscription to push the new state, reads cached `PowerState` directly off `ManagedTv` (in-process, no D-Bus round-trip), retries up to 2 times, then escalates to `self.power_on(tv_id)` if the verify never sees `"active"`. The 40-second power-on budget (probe + WoL flood + reconnect) is owned by `tv_manager::power_on`, so the reliable tier just delegates. Retry-count and verify-delay are per-backend tunables via new `TvBackend::reliable_verify_delay()` / `reliable_max_attempts()` trait methods with sensible defaults; the registry now stores `Arc<dyn TvBackend>` directly so the dispatcher can ask the backend without denormalized constants. System events (`on_wake`, `on_startup`, etc.) flow through the same code path — `tv_manager::execute_system_event` calls `dispatch_action` too, so a `system_profile` with `on_wake = { action = "screen_on", qos.reliability = "reliable" }` gets the same recovery semantics as the user-session unlock event.

**Single source of truth for the cached power-state string.** New `tisvlayd::power_state` module exposes `derive_power_state(&TvState) -> &'static str` plus named `ACTIVE` / `SCREEN_OFF` / `STANDBY` constants; all three derivation sites (`state_forwarder`, `run_subscription_task`, `register_tv_interfaces`'s initial-state seed) and the reliable-tier's short-circuit and verify comparisons go through it. Unit tests pin the table and the literal values.

**`Tv1.GetEffectiveSystemProfile()`** D-Bus method on the daemon, mirroring `Session1.GetEffectiveUserProfile` — returns the resolved system profile as JSON, with each `on_*` slot serialized as a nested `{ action, qos: { reliability } }` table.

**Two field-test bug fixes.** `PowerState::ActiveStandby` joins `ScreenOff` / `Standby` / `Suspend` in `update_power`'s screen-off suppression list; the LG client's `screen_on` / `screen_off` now discriminate by leading error code via `is_idempotent_screen_error(error)` and only mask `500 <message>` as success — everything else (including `-102`) propagates so the reliable tier can react. Both are documented as standalone LG quirks in [docs/lg/firmware-quirks.md](docs/lg/firmware-quirks.md).

**Mock state-injection plus a `screen_on_noop` knob** for testing. `MockHandle::inject_power_state(address, PowerState)` mutates the live `TvState` on an open `MockConnection` and pushes the snapshot through every active subscription, so the daemon's `state_forwarder` updates the cached `Tv1.Power.PowerState` exactly like a real backend-initiated change. `MockHandle::set_screen_on_noop(address, enabled)` makes mock `screen_on` return `Ok` without mutating state — needed to model LG firmware's "screen_on in ActiveStandby succeeds at the wire level but doesn't wake the panel", which the reliable-tier's verify-retry-escalate path is built to detect. Used by four integration tests covering the short-circuit path (cached `"standby"`), the verify-retry-escalate path (cached `"screen_off"` + `screen_on_noop`), and the QoS-aware dedup bypass. `FakeSsapServer` grew a parallel `set_command_error(uri, error_str)` knob for the LG-client error-discrimination regression tests.

**Triage tooling.** [`scripts/triage_dispatch_perf.py`](scripts/triage_dispatch_perf.py) — autonomous reproducer used during the post-merge perf triage. Opens an out-of-band SSAP WebSocket via the daemon's existing `client_key`, sends `ssap://system/turnOff` to put the TV in `screen_off`, then dispatches reliable `screen_on` and times `t0 → PowerState == "active"`. Documented in [docs/testing.md](docs/testing.md) "On-hardware triage tooling".

## Verified on hardware

Repro on the LG OLED G4: lock desktop → press Power on the remote → move mouse. Before this PR the panel stayed dark; after, the reliable tier escalates and the TV wakes back up (~8 s end-to-end). Full annotated journal trace + Bug A / Bug B analysis lives in [docs/lg/firmware-quirks.md](docs/lg/firmware-quirks.md). Headline: on this firmware the TV returns `500` (not `-102`) for `screen_on` in ActiveStandby, so the `PowerState::ActiveStandby` → `is_screen_on=false` mapping (Bug A) is the load-bearing fix; the error-discrimination fix (Bug B) is a real safety net for firmware revisions that return `-102` instead.

### Post-merge perf triage — load-bearing 10 s `REQUEST_MS`

Smoke-testing surfaced a slow trial where the WS went half-dead but the cached state still read `"screen_off"`, so the standby short-circuit didn't fire and `screen_on` stalled the full `REQUEST_MS = 10 s` before erroring out. Three spike branches tried to bypass that wait (timeout race, WS liveness probe, lowered `REQUEST_MS`). All three measurably regressed: 8–10 s saved on the wait, 9–12 s lost on recovery, net pessimization. Mechanism documented in [docs/lg/firmware-quirks.md](docs/lg/firmware-quirks.md) "The 10 s `REQUEST_MS` is load-bearing" — the LG client's `with_retry` reconnect during that wait physically "knocks" the TV awake, which lets the subsequent `power_on`'s WoL → Registration complete in <1 s. The spikes are archived on this branch as cherry-pick + revert pairs (`f384f60`+`6845097`, `4159cba`+`083fb10`) so a future engineer tempted by the same trick can read the per-trial data and the receipts.

## What's deferred

- **TV-side prevention** (Luna `automaticStandBy = "Off"` and friends) — the writing-persistent-TV-settings path would be tisvlay's first such write-level API; the long-tail commitment deserves more deliberation than this PR allows. Full design captured in [docs/ideas/tv-side-power-prevention.md](docs/ideas/tv-side-power-prevention.md).
- **`Capabilities::CONFIGURE_AUTO_OFF` bit + `TvConnection::configure_for_management` trait method** — initially planned as a v1 seam; pulled back to avoid orphan plumbing. The future PR that adds the LG implementation will introduce the capability bit and trait method alongside it.
- **Per-TV reliability override** (today: profile-level only) and **tunable retry / deadline knobs** (today: `reliable` is an opaque bundle). The `qos` namespace is designed to grow into these without schema break.
- **GUI Profiles pane** wiring — small M4 detail that lands with the broader Profiles-pane work; the resolved-profile JSON surface is in place.
