# Socket-access unification + upgrade-safe packaging

Move socket-access policy for the login greeter into the daemon (a greeter-group ACL applied at bind), and fix the maintainer scripts so upgrades don't tear down the running stack. Both came out of a field session on a Fedora 44 GNOME/GDM VM plus upstream research, and together they let us replace a set of per-distro grant hacks that were either broken or divergent.

## Motivation

The greeter socket-access mechanism we shipped (`usermod -aG tisvlay gdm` in the rpm/deb postinstall) is **wrong on the modern dynamic-userdb greeter** and only ever worked in theory on the retired static-`gdm` model. Testing on the VM also shook out two packaging-lifecycle bugs unrelated to the greeter. Rather than patch each distro's grant separately, the research points at one mechanism that is correct wherever the greeter's group is known — a daemon-applied group ACL — which also collapses the NixOS/packaged divergence.

## Findings (grounding)

Modern GDM (GNOME 49+: Fedora 43/44, Ubuntu 25.10+) allocates the greeter through systemd-userdb as a **dynamic** user `gdm-greeter`, uid in the 60578–60705 range, home under `/run/gdm/`, **primary group `gdm`** — not the static `gdm` daemon user (uid 42). A userdb/dynamic account draws no supplementary groups from `/etc/group`, so `usermod -aG tisvlay gdm` targets the wrong account and never reaches the greeter (**confirmed live on Fedora 44**: the greeter EACCES-exits). Upstream GDM solved the same problem for its own polkit/D-Bus policies in 2025 by keying on the **`gdm` group** (`subject.isInGroup("gdm")`), because that group is the stable handle across the migration.

A `g:gdm` **group ACL** on the socket (`g:gdm:rw`) plus `g:gdm:rx` on the runtime dir let the dynamic greeter connect — **validated live on Fedora 44**: the greeter got past its pre-flight, opened its zenoh session, and read the daemon's timeout key.

Two claims from this need reconciling before anything is deleted:

- **The Fedora "static greeter" claims in the repo are stale.** `packaging/scripts/postinstall.sh` and `docs/concerns/greeter-packaged-socket-access.md` still describe Fedora/RHEL/Arch as running the *static* `gdm` greeter (so `/etc/group` is honored). The VM proved Fedora 44 runs the *dynamic* greeter. Those comments/docs were written pre-validation and are now wrong; correcting them is part of this work, not a contradiction to route around.
- **The Ubuntu deferral is NOT closed yet.** `greeter-packaged-socket-access.md` records a *group* ACL (`g:gdm:rw`, mask rw) tested on Ubuntu and **failing**. We validated the ACL only on Fedora and never re-ran the Ubuntu test. The research says Ubuntu 25.10+ uses the same userdb greeter with primary group `gdm`, so the ACL is *expected* to work there too — but the recorded Ubuntu failure must be re-tested and explained on Ubuntu before we delete the Ubuntu deferral. Treat "Ubuntu solved" as a hypothesis to verify, not a result.

The greeter group's **name varies by distro** and must be resolved by name, never by gid: `gdm` on Fedora/RHEL/Arch/Ubuntu, **`Debian-gdm`** on Debian's gdm3 (gid 42 is Fedora-specific). Plasma-login is a separate greeter entirely — its greeter runs as `plasmalogin`, which is **not** in group `gdm`.

NixOS is a third case: `nixos/modules/services/display-managers/gdm.nix` pre-allocates the greeter as **static** accounts `gdm-greeter{,-2..5}` at uid 60578+ (static-emulating the dynamic greeter). Our current `users.groups.tisvlay.members` grant covers both those accounts *and* the plasma-login `plasmalogin` user; it works because they are static. Whether those static accounts carry group `gdm` (the precondition for the ACL to reach them) is **unconfirmed** and must be checked before the members grant is deleted.

Two lifecycle bugs (independent of the greeter):
- **Maintainer scripts don't distinguish upgrade from removal.** On an rpm upgrade the scriptlet order is new-`%post` → old `%preun`, so `preremove.sh` (which unconditionally stops + disables) runs *after* `postinstall.sh` enabled things and undoes them: the daemon is left stopped and units disabled. Reproduced via `dnf reinstall`.
- **No restart-on-upgrade** — even once the above is fixed, an upgrade needs an explicit restart or it keeps running the old binary.

Already landed this session as defensive context: the greeter pre-flights the socket and exits clean on `EACCES` (a stray-enabled greeter is inert, never loops), and the tray survives a missing StatusNotifier host instead of crash-looping (`assume_sni_available`). Both stand regardless of this plan.

## Workstream A — daemon-applied greeter-group ACL

At the existing post-bind step in `crates/tisvlay-daemon/src/lib.rs::open_socket` (creates the runtime dir, then `set_permissions(socket, 0o660)`), additionally apply a POSIX ACL granting a configured **greeter group**: `g:<grp>:rw` on the socket and `g:<grp>:rx` on the runtime directory (the greeter must traverse the `0750` dir *and* write the socket).

Load-bearing details the implementation must get right:
- **Config, wired everywhere — not just NixOS.** Take the group from a daemon option (proposed `--greeter-group <name>`, unset by default → no ACL). The value is the **active display manager's greeter group**: `gdm` (or `Debian-gdm`) for GDM, the plasma-login greeter's group for KWin. The NixOS module's `greeter.enable` passes it per DM, **and** the packaged `tisvlay-daemon.service` `ExecStart` must pass it too (currently it does not) — otherwise deleting the `usermod` grant leaves packaged greeters with no access at all. Since the packaged unit is one file across deb/rpm/arch, the default there is `gdm`/`Debian-gdm`; document that plasma-login packaging (if ever added) needs its own value.
- **Resolve by name, reentrantly.** Resolve `<grp>` via `getgrnam_r` (or an ACL/`nix`/`users` crate that uses it) — never the non-reentrant `getgrnam`, since the daemon runs concurrent NSS-touching adapters (netlink/arp/logind) that share libc's static buffer. Skip cleanly (no ACL, log once) when the group is absent.
- **Mask + chmod ordering.** Adding a named-group ACL entry creates a `mask` entry that also caps the owning `tisvlay` group's *effective* permission, and a later `chmod` recomputes/collapses that mask. So: apply the ACL **after** the `0660` chmod, set the mask to `rw` so both `tisvlay` and the greeter group keep effective `rw`, and never `chmod` the socket again after the ACL is set.
- **Reconcile, don't just add.** The unit sets `RuntimeDirectoryPreserve=restart`, so `/run/tisvlay` (and its ACL) survive daemon restarts; only the socket inode is fresh each bind. On every startup, **reconcile** the directory ACL to the current config — add the greeter-group entry when `--greeter-group` is set, **remove** it when unset — so clearing the flag and restarting actually revokes access instead of leaving a stale grant until a full stop.

This lets us **replace** (once the preconditions below hold): the rpm/deb `usermod -aG tisvlay gdm` + `gpasswd -d` lines; the NixOS `users.groups.tisvlay.members` greeter grant; and the concern doc's "secondary `tisvlay:gdm` socket" recommendation (a plain ACL on the main socket suffices on Fedora). Preconditions before each deletion:
- **Fedora/rpm:** the packaged daemon unit passes `--greeter-group gdm`; then the `usermod`/`gpasswd` lines go, and the stale "static gdm greeter" comment in `postinstall.sh` is corrected.
- **NixOS:** confirm the static `gdm-greeter` accounts carry group `gdm`; keep a grant for the plasma-login `plasmalogin` greeter (either `--greeter-group` set to its group, or retain the members grant for that account only). Do **not** delete the members grant blindly — validation was on a Fedora dynamic greeter, not the NixOS static accounts or plasma-login.
- **Ubuntu:** ~~re-test the ACL on Ubuntu before touching the Ubuntu deferral~~ — **done**: validated on Ubuntu 26.04 (gdm 50, dynamic greeter, `gdm` gid 975 resolved by name); the deferral is closed in the concern doc.
- **Upgrade hygiene:** hosts that installed a pre-ACL package added `gdm` to the `tisvlay` group; since removal-time `gpasswd -d` is going away, add a one-time `gpasswd -d gdm tisvlay` in `postinstall` so the obsolete standing membership is revoked when moving to the ACL model.

Security: the ACL widens socket reach from the `tisvlay` group to also the greeter group (`gdm`), a root-run, trusted display-manager group. It stays opt-in (unset by default) so a daemon with no greeter deployed grants nothing extra; the reconcile step above is what makes "opt-in" actually revocable.

## Workstream B — upgrade-safe maintainer scripts

Guard the removal-only logic in `preremove.sh` so it runs **only on real removal**, in a form correct for the single script nfpm shares across deb/rpm/arch — noting the three managers use three different `$1` conventions:
- rpm `%preun`: numeric count, `0` = final removal, `≥1` = upgrade/reinstall.
- deb `prerm`: string, `remove`/`purge` = removal, `upgrade`/`failed-upgrade` = upgrade.
- pacman `pre_remove`: the package **version string** (e.g. `0.3.0-1`), and pacman calls `pre_remove` **only** on removal (upgrades use `pre_upgrade`).

A guard that matches removal on all three by *excluding upgrades* rather than listing removals: `case "$1" in 1|upgrade|failed-upgrade) : skip ;; *) <stop/disable> ;; esac`. This skips on rpm `1`, deb `upgrade`, and never wrongly skips on pacman (version-string `$1` falls to the default → cleanup runs, which is correct since pacman only reaches `pre_remove` on removal). A naive `[ "$1" = 0 ] || [ "$1" = remove ]` allow-list would silently skip cleanup on Arch and leave the daemon running after `pacman -R`.

Add restart-on-upgrade to `postinstall.sh`: `systemctl try-restart tisvlay-daemon.service 2>/dev/null || true` (a no-op when inactive, so harmless on fresh install; picks up the new binary when an upgrade replaced it under a running daemon). The `|| true` is required — `postinstall.sh` runs under `set -e` and every existing `systemctl` call there is already guarded, or an image build / `--installroot` without a running systemd would abort the scriptlet.

## Workstream C — human desktop-user access + active-session arbitration

The settled part: a group-gated `0660` socket on a *non-root* daemon is a sound, mainstream mechanism (the "docker group == root" critique needs a *root* daemon, which we are not, so socket access confers only TV control), and **the `tisvlay` group stays the authoritative, admin-facing boundary** — NixOS `services.tisvlay.users` is the declarative reference, and explicit membership covers SSH / headless / multi-user / service accounts. **Auto-adding a user in a postinstall is a deliberate, industry-wide refusal**: `$SUDO_USER` is unset under PackageKit / GNOME Software, headless has no human, multi-user has no single "the" user, and no distro policy blesses it (wireshark-common creates the group and explicitly does not add anyone). So the only problem is the *enrollment UX* of the printed `usermod` line — the fix targets the grant step, not the mechanism.

An xhigh review of the first-draft "active-seat ACL, default-on" design plus a code check untangled what had been conflated. The multi-user story is **three orthogonal concerns**, each with its own right layer:

| Concern | Question | Layer / answer |
|---|---|---|
| **Access** | Can this client open the socket? | The `tisvlay` group + a **`pkexec` first-run enroll helper** (below) — durable |
| **Arbitration** | With two users logged in, whose lock/idle automation should fire? | **App layer** — the session service gates its own automation dispatch on `session.active()`; a backgrounded session stays connected but *suppresses* its events |
| **Convenience** | Zero-friction access for the person at the console? | An **active-seat ACL** — deferred at first review, **revived default-on** after #119/#120 (below) |

The load-bearing insight: **"active session" belongs to arbitration, not access.** The first-draft active-seat ACL tried to solve arbitration with access control and did neither cleanly — it *revokes a backgrounded user's connection* when what we actually want is to *keep them connected but ignore their automation while inactive*. Note also (checked in code + the retired design + git history): the arbitration gating was never implemented — the spike/parity plans consciously deferred per-caller/multi-user authorization as a documented single-user-scope gap, and `lock.rs`'s `session.active()` only *selects which* session to watch for `LockedHint`, it does not gate automation.

**Access — a `pkexec` first-run enroll helper.** The GUI / tray / CLI detect "this uid is not in `tisvlay`" and offer a one-click *"Enable TV control for this user"* that runs `pkexec usermod -aG tisvlay $USER` through the desktop's polkit agent, then tell the user to re-login (the standard group-grant caveat — docker/wireshark/libvirt all require it). This keeps the group as the single, durable, auditable boundary, so the session service and every client get durable access, and it works no matter how the package was installed — unlike the postinstall echo, which an app-store / PackageKit install runs as root with no `$SUDO_USER` and so reaches no one. Cost: a one-time authenticated click + re-login, a polkit action, and a little client wiring; needs polkit (standard on desktops). NixOS keeps declarative `services.tisvlay.users`; the packaged `usermod` echo drops to a documented fallback.

**Access — done** (PR #120). Shipped as CLI + GUI, not tray/session (the session service *consumes* access, it can't self-enroll). The shared helper lives in **`tisvlay-core` behind an `access` feature** (`has_access()` / `enable_access()` → a structured `EnrollOutcome`; raw-`libc` group/user resolution mirroring `acl.rs`, no printing so each surface renders the outcome its own way) — not `tisvlay-wire` (a protocol crate the servers import) nor the SDK (the CLI is deliberately a pure-zenoh client, no SDK dep). No custom polkit action: `pkexec usermod` rides the default `org.freedesktop.policykit.exec` admin auth, so there is no rule to ship. Surfaces: `tisvlay enable-access` (dispatched *before* opening the client — it is the fix for not being able to connect) plus a no-access hint on any connect failure (the group-owned runtime dir isn't searchable, so `Path::exists()` on the system socket reads EACCES as absent and socket resolution lands on the dev path → the CLI now checks `has_access` and points at `enable-access` instead of a misleading "daemon unreachable at `/run/user/…`"); and an app-level GUI banner (new `Errors.access` slot above every pane, reusing the `InlineError` widget) whose button runs the enroll off the UI thread and reports the outcome. Field-validated on Fedora 44 + GNOME: banner → polkit password dialog → real `usermod` → access after **reboot**. Note the re-login caveat is sharper than "log out and back in": a plain GNOME logout/login did *not* pick up the new group, because the systemd per-user manager (`user@UID.service`) outlives a logout and keeps its group set frozen at first-login (supplementary groups are fixed at process spawn), so the new session re-attaches to the stale manager — a reboot (or `loginctl terminate-user`) is the reliable path, and the enroll-success copy (CLI + GUI) now says so.

**Arbitration — active-session gating in the session service (new).** The session service already holds the logind `session.active()` proxy (used today only to pick the `LockedHint` session). Extend it to gate *automation dispatch* **absolutely**: while the user's session is not the seat's foreground session, the service stays connected (via the group) but **suppresses every automation event**, full stop — the "exclusive control to the active user" originally intended, done at the layer where it belongs, with no ACL. The gate must be absolute, not a fuzzy off-going/on-going split: on a *shared* TV (two users whose profiles target the same set — a common living-room box) a backgrounded user's lock→off would turn off the TV the active user is watching, a real conflict, so no event class is "always safe." Check `active` at event-dispatch time: locking does *not* deactivate a session (only switching away does, and that happens after the lock), so a lock→off fires while the session is still active and is delivered normally; only genuinely-backgrounded events are dropped. The residual cost — a narrow race where a session deactivates before its own lock is processed leaves that user's TV on until they return — is predictable and acceptable, and far better than the shared-TV conflict a fuzzy rule would allow. Scope items: unconditional vs a global opt-out (single-user makes it a no-op either way), and confirm the greeter idle client (its own always-foreground greeter session) is unaffected.

**Arbitration — done** (PR #119). The session service seeds an `is_active: Arc<AtomicBool>` from `session.active()` and follows `receive_active_changed()` in the lock watcher; `SessionStack`/`Core` gate seat-local automation dispatch on it — `event.is_seat_local() && !is_active` drops the event after the audit tap, before the per-TV loop. Default `true`, so startup and non-logind hosts never suppress. The greeter idle client is unaffected (its greeter session is always the seat foreground). Went in unconditional (no global opt-out — single-user makes it a no-op).

**Convenience — active-seat ACL (revived, default-on).** Deferred by the first review on three grounds; re-evaluated after the other two legs shipped, because two of the three dissolved and QA taught us something new. (a) The killer — *a transient grant is the wrong primitive for the persistent session service* (fast-switched-away user + Workstream B's own `try-restart` → reconnect denied → that user's automation silently dead) — is moot post-#119: while a session is backgrounded its automation is suppressed *by specification*, so the denied window and the suppressed window are now the same window; what matters is recovery on return, which the resilient links' retry loop provides. (b) The enroll path's hidden cost surfaced in #120's QA: a group grant does not take effect on logout/login (the systemd per-user manager keeps the stale group set), so the durable path's honest instruction ends in "reboot your computer" — while a seat ACL attaches to the *socket*, not any process's credentials, so the GUI's already-retrying link connects seconds after the grant lands: install → open app → it works, no click, no polkit, no reboot. It also restores runtime-dir traverse, killing the misleading dev-path fallback error for console users. (c) The security cluster stays real and is addressed by the gates + posture below. Precedent (2026 research): no upstream daemon ACLs its own listening socket; the composition is systemd's in-process `/run`-ACL-for-a-uid (journald user journals, coredump, exec credentials) + `uaccess`'s active-seat semantics — and `uaccess` itself is udev/device-node-only, which is why this must live in-daemon. Upstream's own posture backs presence over static groups: "using static groups to grant unprivileged users device access is a concept which has been discouraged for a while" (systemd#4288).

Load-bearing details the implementation must get right:
- **Seat watch, not session scan.** A daemon task beside `watch_logind` on the existing system-bus connection: `ListSeats` + each seat's `ActiveSession` property stream (plus `SessionNew`/`SessionRemoved` for churn); resolve the active session's `(uid, Class, Type, Remote)` and grant iff `Class=user` ∧ `Type∈{x11,wayland}` ∧ `Remote=no`. Never select sessions by `Active=yes` — live Fedora data shows an SSH shell as `Remote=yes Type=tty Class=user Active=yes`. The `Class=user` gate also excludes the greeter session (`Class=greeter`), which stays covered by Workstream A's group entry. Multi-seat falls out naturally: one entry per qualifying seat session, so the desired state is a uid *set*.
- **`acl.rs` generalized to desired-state.** Desired ACL = base mode + `{greeter group}` ∪ `{active seat uids}`; the fixed five-entry emitter becomes a sorted entry set — `ACL_USER` tag `0x02` between `USER_OBJ 0x01` and `GROUP_OBJ 0x04`, ids ascending within a tag — and every named entry carries full `rw`, because ACL evaluation is first-match-by-class: a named-user entry decides that user alone, so a narrower entry would *subtract* access from a user who is also a group member. Mask stays `rw`. Socket gets `u:<uid>:rw`, runtime dir `u:<uid>:r-x`. Reconcile on every seat event and at startup — the preserved runtime dir can carry a stale uid from before a crash, so startup recomputes from logind ground truth (`ListSeats` → `ActiveSession`), never trusts what it finds.
- **Transience is the spec, not a trap.** Switch-away removes the entry: new connects are denied exactly while #119 suppresses that user's automation. Existing connections persist (the kernel checks permission at `connect()`) and are benign — a backgrounded GUI is a read-only mirror, and `uaccess` accepts the same property for device fds. On return the entry re-lands and the resilient links reconnect; implementation must check the zenoh retry ceiling keeps that lag small, and the on-local-return wake's race with reconnect rides the existing no-reply RPC retry.
- **Posture: default-on; the group stays the durable boundary.** The daemon binary defaults the grant on (`--seat-access=false` disables), so the packaged unit needs no flag at all and the NixOS option (`seatAccess`, default true) only ever emits the opt-out — an opt-in flag a novice never finds fixes nothing, and Workstream A already made auto-detection the packaged default for the greeter. Docs reframe accordingly: the `tisvlay` group is the *durable* boundary (SSH, remote, headless, linger — `enable-access` is its one-click enrollment); console presence is an additional, presence-scoped grant. Hosts without logind degrade to group-only. Between the two legs, no one ever types `usermod`.
- **Client coherence ships in the same PR.** `has_access` becomes a connect-probe — `EACCES` ⇒ no access; any other failure ⇒ access-but-daemon-unreachable (the same discrimination the greeter EACCES check from #118 uses) — otherwise the GUI banner would nag a console user whose access already works. The `enable-access` verb stays group-based: it manages the durable grant.
- **Testable without logind.** The grant-mid-run path is exactly "socket perms widen while a resilient link retries": boot a daemon on a locked-down socket, assert a client is denied, widen, assert the link comes up. Plus emitter unit tests (tag order, mask, uid-set churn) and seat-watch coverage over the private-bus fakes (`tisvlay-test`).

**POSIX ACL evaluation — corrected (for the greeter ACL and any future seat ACL).** The kernel evaluates an ACL by *first-matching class*, not as a union: owner → named-user entries → (owning group + named-group entries) → other, stopping at the first class the caller matches. A caller matched by a named-user (`ACL_USER`) entry is decided by *that entry alone* (mask-clamped) and never falls through to the owning group — so a named-user entry must itself carry the perms that user needs (`rw` to `connect()` a socket), and a narrower one would *subtract* access from a user who is also a group member. (The first draft's "two additive layers, ORed by the kernel" was wrong.) Immaterial to Workstream A's greeter ACL, which only ever writes a group entry.

**Unit-enablement convergence (minor, mostly done).** NixOS uses declarative `wantedBy`; packaging uses `systemctl --global enable`. Workstream B fixed the upgrade/removal correctness bug; fuller convergence (systemd presets) is optional and not pursued here.

## Sequencing

1. **A — done.** Daemon greeter-group ACL + per-target wiring; field-validated on Fedora 44 and Ubuntu 26.04, eval-verified on NixOS, same `--greeter-access` unit on Arch; the redundant `usermod`/`gpasswd` and stale docs removed.
2. **B — done.** Upgrade-safe maintainer scripts (guard teardown on `$1`, `try-restart` on upgrade); field-validated on Fedora.
3. **C — access + arbitration done; convenience revived.** Arbitration shipped in PR #119 (active-session gating of automation dispatch in the session service). Access shipped in PR #120 — a `pkexec` first-run enroll helper (CLI `enable-access` verb + no-access hint, GUI banner; shared helper in `tisvlay-core`'s `access` feature), field-validated on Fedora 44. Convenience → re-evaluated after both landed (#119 made the transient-grant objection moot; #120's QA exposed the group path's reboot requirement): the active-seat ACL is back on, **default-on**, per the design above — branch `feat/seat-access`. The xhigh review corrected the first draft's ACL-evaluation model, logind/`acl.rs` "reuse" claims, and CLI-resilience/precedent statements; those are folded in above.
