# Network link recovery

A network TV whose link drops while the TV stays on is never redialed today, and a screen request sent to it while it is down is acked as already done. After a Wi-Fi router's firmware reboot on 2026-11-15 this left the office LG running its own screen saver over the PC's input for hours: TisVlay could neither see nor blank it. This plan makes the daemon redial such a TV until the network is back, makes the session decide again about its panel when the link returns, and makes the next incident readable from the logs.

## What happened

Reconstructed on the packaged 0.6.0 stack. The system journal before about 08:00 was gone (a crash-looping unit outside TisVlay filled journald's size cap), so the daemon's side comes from the timestamps of its zenoh samples, and the TV's from read-only SSAP probes.

| When (CST) | What |
|---|---|
| 11-14 11:07 | The LG's last power report: on, screen off. Later screen-offs (an idle timeout, Moonshine stream starts and ends) changed nothing, so nothing was republished. The session stayed idle from 11:11 on. |
| 11-15 01:02:39 | During the router reboot the LG's link went down. No dial followed: no `connect-failed`, never `reconnecting`. |
| 01:06:54 | The network was back (a Moonshine client reconnected). |
| 03:14:20 | A stream ended; the session sent Screen Off. The daemon acked it as satisfied without sending anything. |
| 07:56 | The TV reported power On over CEC. |
| 12:46 | Probe: the TV's power state is `Screen Saver`, HDMI 1 in front with a signal. Re-probed after five live stream events at 12:48–12:49: unchanged, with five Screen Offs acked and dropped. |

The host's own network never changed (no carrier transition, the route to the TV stayed in the FIB), so neither the carrier nor the route watcher had anything to report, and those are the only things that redial a parked network TV. The session's profile had both idle timeouts set (5 s locked, 300 s unlocked).

## The code paths

- **A network TV's drop never redials.** `BackendEvent::Disconnected` (`tisvlay-world/src/systems/facts.rs`) redials only local-device TVs. `disconnect_stays_down_until_reconnect_command` pins it, reasoning that a drop means the user turned the TV off.
- **A dial streak gives up after three attempts** (the `ConnectFailed` arm), unless a local device can't be opened.
- **Screen Off on a disconnected TV is a no-op** with no dial pending (`tisvlay-world/src/systems/dispatch.rs`, `None if !on => Ok(())`), and is latched for the reconnect with one pending (`DispatchVerify`, re-sent by the `Connected` arm). `disconnected_screen_off_is_a_satisfied_noop` and the boot-wake latch test in the dispatch suite pin the two.
- **The session already re-blanks a panel that lights itself while idle.** `arm_drift` / `reassert_due` (`tisvlay-session/src/lib.rs`): a TV that reports lit while an idle action holds gets one idle timeout of grace, then the idle action goes out again, if the desk is still idle, the panel still lit and the TV still `automated` (managed, and the `automate_when` / `primary_input` gate holding against its current input). It reads the panel from `state/power` alone and ignores `state/link`, so it saw neither the outage nor the TV's return.

The first three are right for a TV that went to standby and wrong for one that is on behind a network outage. The difference is visible: an LG announces a standby (its power report goes to `ActiveStandby` or `Standby`) before it closes the link, and a daemon power-off closes the link from the daemon's side.

## Decisions

1. **A drop is unannounced unless the TV said it was going off or the daemon turned it off.** Announced: the last power report was in the off class (`Standby`, `ActiveStandby`, `Suspend`) or `CoolingDown`, or the connection closed after its own power-off, which the connection task reports with the drop (a power-off the TV never received counts too: the daemon asked for off). Everything else, `Unknown` and `WarmingUp` included, is unannounced. A screen-off in flight doesn't announce anything, and neither does a power-off expectation left from an earlier sleep, so the rule reads the connection, not `PowerEdge` or `SendingOff`. *Why:* redialing too little is the incident; redialing a TV that is off costs a refused dial a minute and reconnects it the moment it is back on.
2. **An unannounced drop redials until the link is back.** The first dial follows the drop at once; the streak then keeps going past the three-attempt budget on the existing backoff (3 s, doubling to a 60 s cap), the way a local device that can't be opened already does. `event/connect-failed` reports the budgeted attempts only. The streak is a marker of its own, so a `redial()` from a reload, a re-pair or a route change doesn't wipe it. A wake during the outage (a screen-on, a power-on, a resume) spends its own budget and falls back to the streak. `reconnect`, and the carrier or route returning, dial at once instead of waiting out the backoff. The streak ends when a dial connects or the TV is removed. The dial gate is unchanged, so a TV whose route or device is known gone still waits for it. *Why:* a router reboot takes minutes, and the first mouse touch during an outage must not put the TV back where the incident left it. A plain dial never powers a TV on.
3. **A network TV that spends its budget with nothing answering enters the streak instead of giving up, managed or not.** A daemon started during an outage (a package upgrade restarts it) has no last report to judge by; today it dials three times, stops, and from then on acks screen-offs for a TV it has "never seen". Within the budget nothing changes, so a boot dial still latches a screen-off that races it. Only a dial nothing answered counts: the network refused it, it timed out, or the link closed under it. A TV that answers and turns the dial down (a rejected key) or a config that can't be dialed keeps the three-attempt budget, and such an answer ends a streak under way. *Why:* it is the incident again by another door, and the cost is the one decision 1 already accepts; `managed` gates automation and not connectivity, so the rule doesn't read it; and a refusal isn't an outage, with an LG prompting for pairing each time it is asked with a key it has forgotten.
4. **Parking an awake TV is an unannounced drop too.** A carrier or route loss on the PC's side parks the connection; when the link returns before the path to the TV does, the redial is the same streak, not three dials. Nothing dials while parked. *Why:* it is the same outage seen from the other end.
5. **The daemon holds nothing for a TV in the streak.** A screen-off or power-off to it is refused with `not-connected`: the rpc and a profile action alike, a held wake or not. A screen request still being verified when the link drops is dropped with it, and a wake that falls back to the streak takes its screen intent and its input restore with it. The test is the streak's marker, never whether a dial happens to be pending, so the latch a screen-off gets behind a boot dial or a wake after an announced off is unchanged. A screen-on keeps its wake path. A screen-off to a TV that was never dialed past its budget and never seen awake stays a satisfied no-op. The world's own actions refused this way (a connector's DPMS-off, the greeter's idle) are logged at info. *Why:* a request held for the reconnect goes stale: what should happen to the panel when the TV is back depends on what is true then, and the daemon doesn't own those reasons.
6. **No new time constants.** Nothing in this plan adds a timeout, a bound or a grace period; the backoff, the budget and the idle timeouts are the ones already there. *Why:* a bound on a held request is a guess at how long an outage lasts, and every wrong guess is either the incident or a blanked TV someone is watching.
7. **The session reads a panel as lit only while the TV is connected and reports lit, and remembers nothing.** It follows `state/link` as well as `state/power`, so a TV that returns lit is a dark-to-lit change like any other and takes the existing drift path: one idle timeout of grace, then the idle action, if the desk is still idle and the TV still automated against its fresh input. That covers a TV that drifted during the outage, an idle timeout that fired during it, and an idle action that was acked and lost with the link, with no record of what was refused. *Why:* the session knows whether the desk is still idle and the input gate still holds; a person who woke the PC or switched the TV's input meanwhile is left alone by the gates that already exist, and a rule over levels can't go stale or be lost with a restart.
8. **What the session's rule doesn't cover is said, not patched.** The re-blank needs the idle timeout for the desk's state to be set: with a locked idle timeout of 0, a desk that idled unlocked and then locked holds no idle action, and a TV back lit stays lit. An unlock or idle-resume during the outage can't light the TV, and nothing lights it on the return. A TV blanked for a stream, not by idle, isn't watched for drift. The first is documented where the idle timeouts are; the other two go to `docs/ideas/`. *Why:* each needs a rule of its own (what a lock holds, when a wake is still wanted, where a stream's window ends), and the incident needs none of them.
9. **Visibility:** the daemon logs at info a network TV's drop with its last power state and whether it redials, and the link's return with how many dials it took; the session logs each profile action's outcome, the refusals at warn. *Why:* the incident's cause survived only in zenoh sample timestamps.
10. **The commits are `fix`.** A screen-off that used to ack now answers `not-connected` in one more case, with an existing code on an rpc that already returns it; no key, payload, rpc or decode rule changes, which is what the wire rule guards. The commit bodies say what a client now sees.
11. **Tests first, ignored.** The failing tests land with the plan, each `#[ignore = "…"]` naming the gap it shows, so every commit passes `just check`; the commit that closes a gap removes its ignores.
12. **Out of scope, to `docs/ideas/`:** a WebSocket ping for a link that dies silently (it needs an interval; the incident's drop was a clean close); showing an unseen TV's power state as unknown (`state/link` already says it is down, and decision 7 stops the session from trusting it); the world re-deciding its own standing conditions on a link's return; a tray warning for a long outage; a laptop on a foreign network dialing its home TV's private address once a minute; and the two gaps of decision 8.

## Steps

Each step is a commit on `fix/network-link-recovery`, passing `just check`, and carries the docs it makes untrue.

1. **The plan and the failing tests** (the plan commits, each revision after a review stacked on the last). The mock backend learns to cut a live link without a power change (`MockHandle::cut_link`), to refuse dials during an outage (`set_unreachable`), to have a screen-off find the link dead (`set_screen_off_closes`) and to power off without a standby report (`set_power_off_unreported`); its senders become weak, with the shared registry holding the only strong ones, and a dropped connection removes only its own registrations, which a mock unit test pins. `tisvlay-world`'s `link_recovery` suite: nine ignored tests and two guards that pass today (a drop after a standby report, and a power-off without one, stay down). `tisvlay-session`'s suite: three ignored tests. `docs/testing.md` lists the suite and the knobs. *Verified by:* `--run-ignored all` fails the twelve, each at its first missing behavior; everything else passes.
2. **Redial after an unannounced drop** (decisions 1–3), with the daemon's log lines of decision 9. Docs: `docs/architecture.md` § The world ("a network TV that goes down stays down until asked") and its dial-budget sentence; the book's `operations/networking-reliability.md` ("stays down until asked"); the doc comments on `disconnect_stays_down_until_reconnect_command`, the carrier suite's header and `PendingConnect`. *Verified by:* the redial, backoff, screen-off-noticed, power-off, wake, `reconnect` and started-mid-outage tests pass with their ignores gone, as does the session's back-lit test; `disconnect_stays_down_until_reconnect_command` and both guards still pass; `connect_failure_backs_off_and_gives_up` is rewritten for an unmanaged TV, the reason in the commit body; the device suite's one-backoff delay for a local device is unchanged; the log lines are asserted with `traced_test`, `tracing-test` joining the world crate's dev-dependencies. *Done (2026-11-15):* as planned, with the differences under Deviations.
3. **Parking an awake TV** (decision 4). Docs: `docs/watchers/network.md`'s parking section. *Verified by:* the parked-by-carrier test passes with its ignore gone; the carrier suite, which pins no dial while parked, unchanged. *Done (2026-11-15):* the parked test had passed since step 2 (Deviations); this step marks a TV parked while on and has the carrier or route returning dial at once, pinned by a new test.
4. **The daemon holds nothing for a TV in the streak** (decision 5). Docs: `docs/architecture.md`'s screen-latch paragraph (the latch no longer survives into a streak; a disconnected screen-off is a no-op only for a TV never seen); the book's reliability page ("the reconnect re-asserts what you asked for"); the SDK's `screen_off` doc comment ("a disconnected TV already counts as dark"). *Verified by:* the refused screen-off test passes with its ignore gone, and the wake test's refusal and its zero sends; `disconnected_screen_off_is_a_satisfied_noop` and the boot-wake latch test still pass; a new test that a profile power-off in the streak is refused. *Done (2026-11-15):* as planned; a TV parked while on refuses a screen-off too, and a TV entering the streak from a spent budget drops what was latched behind its dials.
5. **The session's panel rule and its outcome log** (decisions 7–9). Docs: `docs/architecture.md`'s session paragraph gains the rule; the book's page on idle timeouts says the re-blank needs one set. *Verified by:* the session's two remaining tests pass with their ignores gone; `screen_drift_while_idle_reasserts_after_grace` still passes; the outcome log by a test in the session suite, which the idle-during-outage test then waits on.
6. **On the TV.** A `docs/bugs/` entry for the incident is opened (indexed under Open) with the check as a fish block, in the shape `docs/cec/checks.md` uses for unattended checks (the test TV is the host's only display): variables for the TV's address and id, `sudo -v`, a named nftables table rejecting traffic to the TV with ICMP net-unreachable, the daemon's socket to the TV killed with `ss -K` so the drop is certain rather than waiting on a send (its kernel requirement stated), the daemon's timestamped samples and journal recorded throughout, a read-only SSAP probe of the TV before and after, the table deleted at the end, and the profile's idle timeouts recorded. Three passes, results dated and by TV model: 0.6.0, to reproduce; the branch; and the branch with the TV turned off by its remote during the outage. *Verified by:* on 0.6.0 the link stays down; on the branch it returns within a backoff period of the table's removal, and a TV found lit while the session is idle goes dark after the profile's idle timeout; in the third pass the dials neither wake the TV nor keep it out of deep standby. If the third fails, decision 1's "redial a TV that is off" is wrong for this TV and is revisited before the merge. The passes also answer whether the LG leaves Screen Off by itself when its client drops.
7. **Docs, and retire the plan.** The bug entry is closed in the repo's shape (status naming the pinning tests, severity, symptom, cause, fix) with the timeline and the check's results; the decisions' reasons go to `docs/architecture.md`; `docs/watchers/network.md` gains the remote-side outage in its scenarios, with the lesson that carrier and route can't see it; the LG findings go to `docs/lg/firmware-quirks.md`; the book's troubleshooting material points at the new log lines; decision 12's items get their `docs/ideas/` entries and index lines; this file is deleted and its index entry removed.

## Deviations

- **Before any code (first review):** the first draft had the daemon keep the last screen request per TV and re-send it on the reconnect, and a power-off end the redial. The review showed that replaying a request can blank a TV a person has since woken, and that every fix for it was a time bound. The session's drift re-assert already decides this with the right gates, so the daemon holds nothing (decisions 5 and 6), and the tests that pinned the hold were replaced.
- **Step 2, after it landed:** the first cut sent any managed TV into the streak after three failed dials of any kind. That retried a broken config forever, would have had an LG that forgot its key prompt for pairing once a minute, and read `managed` for a connectivity decision, against the architecture's own invariant. The follow-up commit has the dial failure say whether anything answered, and drops `managed` from the rule (decision 3, as amended).
- **Step 2:** the parked-by-carrier test passes here already, since a managed TV that spends its budget is dialed on whatever parked it (decision 3); step 3 is left with the dial at once on the carrier's or route's return. `connect_failure_backs_off_and_gives_up` needed no rewrite (its TV fails on its config, before any dial). The wake test and the started-mid-outage test keep an ignore for their refusal half, which is step 4's.
- **Before any code (second review):** the session was to remember idle actions the daemon refused and send them on the link's return. It can't see a link return today, the memory could go stale, and it would be lost with a session restart; reading the panel as lit only while connected gives the same result from levels (decision 7). A stream-blanked TV's drift was dropped for want of a window (decision 8), and the daemon started mid-outage was taken in (decision 3).
