# Network link recovery

A network TV whose link drops while the TV stays on is never redialed today, and a screen request sent to it while it is down is acked as already done. After a Wi-Fi router's firmware reboot on 2026-11-15 this left the office LG running its own screen saver over the PC's input for hours: TisVlay could neither see nor blank it. This plan makes the daemon redial such a TV until the network is back, makes whoever asked for a dark panel decide again when the link returns, and makes the next incident readable from the logs.

## What happened

Reconstructed on the packaged 0.6.0 stack. The system journal before about 08:00 was gone (a crash-looping unit outside TisVlay filled journald's size cap), so the daemon's side comes from the timestamps of its zenoh samples, and the TV's from read-only SSAP probes.

| When (CST) | What |
|---|---|
| 11-14 11:07 | The LG's last power report: on, screen off. Later screen-offs (an idle timeout, Moonshine stream starts and ends) changed nothing, so nothing was republished. The session stayed idle from 11:11 on. |
| 11-15 01:02:39 | During the router reboot the LG's link went down. No dial followed: no `connect-failed`, never `reconnecting`. |
| 01:06:54 | The network was back (a Moonshine client reconnected). |
| 03:14:20 | A stream ended; the session sent Screen Off. The daemon acked it as satisfied without sending anything. |
| 07:56 | The TV reported power On over CEC. |
| 12:46 | Probe: the TV's power state is `Screen Saver`, HDMI 1 in front with a signal. Re-probed after five live stream events at 12:48–12:49: unchanged, with five Screen Offs acked and dropped. |

The host's own network never changed (no carrier transition, the route to the TV stayed in the FIB), so neither the carrier nor the route watcher had anything to report, and those are the only things that redial a parked network TV.

## The code paths

- **A network TV's drop never redials.** `BackendEvent::Disconnected` (`tisvlay-world/src/systems/facts.rs`) redials only local-device TVs. `disconnect_stays_down_until_reconnect_command` pins it, reasoning that a drop means the user turned the TV off.
- **Screen Off on a disconnected TV is a no-op.** The screen dispatch (`tisvlay-world/src/systems/dispatch.rs`, `None if !on => Ok(())`) treats a disconnected TV as dark. `disconnected_screen_off_is_a_satisfied_noop` pins it, for a TV that never connected.
- **The session already re-blanks a panel that lights itself while idle.** `arm_drift` / `reassert_due` (`tisvlay-session/src/lib.rs`): a TV that reports lit while an idle action holds gets one idle timeout of grace, then the idle action goes out again, if the desk is still idle, the panel still lit and the TV still `automated` (managed, and the `automate_when` / `primary_input` gate holding against its current input). With the link dead it never saw the lit panel.

The first two are right for a TV that went to standby and wrong for one that is on behind a network outage. The difference is visible: an LG announces a standby (its power report goes to `ActiveStandby` or `Standby`) before it closes the link, and a daemon power-off closes the link from the daemon's side.

## Decisions

1. **A drop is unannounced unless the TV said it was going off or the daemon turned it off.** Announced: the last power report was in the off class (`Standby`, `ActiveStandby`, `Suspend`) or `CoolingDown`, or the connection closed after its own power-off, which the connection task reports with the drop. Everything else, `Unknown` and `WarmingUp` included, is unannounced. A screen-off in flight doesn't announce anything, and neither does a power-off expectation left from an earlier sleep, so the rule reads the connection, not `PowerEdge` or `SendingOff`. *Why:* redialing too little is the incident; redialing a TV that is off costs a refused dial a minute and reconnects it the moment it is back on.
2. **An unannounced drop redials until the link is back.** The first dial follows the drop at once; the streak then keeps going past the three-attempt budget on the existing backoff (3 s, doubling to a 60 s cap), the way a local device that can't be opened already does. `event/connect-failed` reports the budgeted attempts only. The streak is a marker of its own, so a `redial()` from a reload, a re-pair or a route change doesn't wipe it. A wake during the outage (a screen-on, a power-on, a resume) spends its own budget and falls back to the streak. `reconnect`, and the carrier or route returning, dial at once instead of waiting out the backoff. The streak ends when a dial connects or the TV is removed. The dial gate is unchanged, so a TV whose route or device is known gone still waits for it. *Why:* a router reboot takes minutes, and the first mouse touch during an outage must not put the TV back where the incident left it. A plain dial never powers a TV on.
3. **Parking an awake TV is an unannounced drop too.** A carrier or route loss on the PC's side parks the connection; when the link returns before the path to the TV does, the redial is the same streak, not three dials. *Why:* it is the same outage seen from the other end.
4. **The daemon holds nothing for an unreachable TV.** A screen-off or power-off to a TV in the streak is refused with `not-connected`, for the rpc and for a profile action alike, and a screen request still being verified when the link drops is dropped with it. A screen-on keeps its wake path. A screen-off to a TV the daemon has never seen awake stays a satisfied no-op. *Why:* a request held for the reconnect goes stale: what should happen to the panel when the TV is back depends on what is true then, and the daemon doesn't own those reasons. Holding would need an expiry, and an expiry is a guess.
5. **Whoever wanted the panel dark decides again when the link returns.** For the session, a TV's link coming back is an event like any other. A lit panel found on the return is drift, and takes the existing path: its grace is the profile's own idle timeout, and it re-sends only while the desk is still idle and the TV still automated against its fresh input. An idle action that was refused during the outage goes out on the return, under the same conditions. A TV blanked for a stream is watched for drift the same way while the stream lasts. *Why:* the session knows whether the desk is still idle, a stream still runs, and the input gate still holds; a person who woke the TV or switched its input in the meantime is left alone by the gates that already exist.
6. **No new time constants.** Nothing in this plan adds a timeout, a bound or a grace period: the backoff, the budget and the idle timeouts are the ones already there.
7. **Visibility:** the daemon logs at info a network TV's drop with its last power state and whether it redials, and the link's return with how many dials it took; the session logs each profile action's outcome, the refusals at warn. *Why:* last night's cause survived only in zenoh sample timestamps.
8. **Tests first, ignored.** The failing tests land with the plan, each `#[ignore = "…"]` naming the gap it shows, so every commit passes `just check`; the commit that closes a gap removes its ignores.
9. **Each step carries its docs.** `docs/architecture.md` § The world and the book's networking-reliability page both say a network TV that goes down stays down; the step that changes that changes them.

## Open for review

- **Is refusing a screen-off that used to ack a `fix`?** No key, payload, rpc or decode rule changes, and `not-connected` is an existing code, but a client that sent a screen-off to an unreachable TV now gets an error where it got an ack.
- **The daemon's own standing conditions.** The world owns some reasons for a dark panel itself (a connector's DPMS-off, the greeter's idle). Decision 5 covers the session's; whether the world re-decides its own on a link's return, and which of them are levels it can read, isn't settled.
- **A daemon started mid-outage** dials three times and gives up, with no last report to judge by. Taking it in means a managed network TV's boot dial never gives up either.
- **A link that dies silently.** The LG client sends no WebSocket ping, so a half-open link isn't noticed until a command times out. Last night's drop was a clean close.
- **Stale `state/power` while down.** Clients show the last report ("on, screen off") for a TV nobody can see; `state/link` already says it is down.

What isn't taken in goes to `docs/ideas/` with an index entry, along with a tray warning for a long outage, which is a feature of its own.

## Steps

Each step is a commit on `fix/network-link-recovery`, passing `just check`.

1. **The plan and the failing tests** (two commits: the baseline, then its revision after review). The mock backend learns to cut a live link without a power change (`MockHandle::cut_link`), to refuse dials during an outage with `NetworkUnreachable` (`set_unreachable`), and to have a screen-off find the link dead (`set_screen_off_closes`); its subscription sender becomes weak, with the shared registry holding the only strong one, and a dropped connection removes only its own registrations. `tisvlay-world`'s `link_recovery` suite: seven ignored tests (the redial until the network is back; a drop noticed by a screen-off; a refused power-off with the redial going on; a refused screen-off with nothing held; a wake that keeps the redial; a `reconnect` that dials at once; an awake TV parked by a carrier loss) and one guard that passes today (a drop after a standby report stays down). `tisvlay-session`'s suite: three ignored tests (a TV back lit from an outage is re-blanked while idle; an idle action refused during an outage lands when the link returns; a stream-blanked TV back lit is re-blanked). `docs/testing.md` lists the suite and the knobs. *Verified by:* `--run-ignored all` fails the ten, each at its first missing behavior; everything else passes.
2. **Redial after an unannounced drop** (decisions 1–3), with the info logs of decision 7 on the daemon's side, and `docs/architecture.md` and the book's page saying what is now true. *Verified by:* the six redial tests in the world suite and the session's back-lit test pass with their ignores gone; `disconnect_stays_down_until_reconnect_command` (a user power-off) and the standby guard still pass; the carrier, device and held-wake suites unchanged; the log lines asserted with `traced_test` in the world suite.
3. **The daemon holds nothing for an unreachable TV** (decision 4). *Verified by:* the refused screen-off test passes with its ignore gone; `disconnected_screen_off_is_a_satisfied_noop` still passes; the dispatch suite unchanged apart from tests that pinned a hold across a plain redial, each rewritten with its reason.
4. **The session decides again on a link's return** (decision 5), and logs outcomes (decision 7). *Verified by:* the session's two remaining tests pass with their ignores gone; `screen_drift_while_idle_reasserts_after_grace` still passes; the outcome log by a test in the session suite.
5. **On the TV.** The check is a fish block in a new `docs/bugs/` entry for this incident, in the shape `docs/cec/checks.md` uses for unattended checks (the test TV is the host's only display): `sudo -v`, a dedicated nftables table rejecting traffic to the TV with ICMP net-unreachable and removed at the end, the daemon's socket to the TV killed with `ss -K` so the drop is certain rather than waiting on a send, the daemon's timestamped samples and journal recorded throughout, and a read-only SSAP probe of the TV before and after. Run once on 0.6.0 to reproduce and once on this branch, results dated and by TV model. A second pass turns the TV off with its remote during the outage, to see that the dials neither wake it nor keep it from deep standby. *Verified by:* on 0.6.0 the link stays down; on the branch it returns within a backoff period of the table's removal, and a TV found lit while the session is idle goes dark after the profile's idle timeout. The run also answers whether the LG leaves Screen Off by itself when its client drops.
6. **Docs, and retire the plan.** The incident, its timeline and the check's results stay in the `docs/bugs/` entry, closed, naming the tests that pin the fix; `docs/watchers/network.md` gains the remote-side outage in its scenarios, with the lesson that carrier and route can't see it; the LG findings go to `docs/lg/firmware-quirks.md`; what the review leaves of "Open for review" goes to `docs/ideas/`; this file is deleted and its index entry removed.

## Deviations

- **Before any code:** the first draft had the daemon keep the last screen request per TV and re-send it on the reconnect, and a power-off end the redial. The plan review showed that replaying a request can blank a TV a person has since woken, and that every fix for it was a time bound. The session's drift re-assert already decides this with the right gates, so the daemon now holds nothing (decisions 4–6), and the tests that pinned the hold were replaced.
