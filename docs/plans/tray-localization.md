# Tray localization (gettext-rs)

Bring `tisvlay-tray` to the same i18n standard as `tisvlay-gui`: wrap user-facing literals with `gettext`, ship a per-locale `.po`/`.mo` catalog under `crates/tisvlay-tray/lang/`, and extend the existing `just i18n-*` recipes to cover both crates. v1 ships English only — the infra lands so translators can drop a `.po` and `cargo build` picks it up, matching the GUI's current state.

## Motivation

Today the tray ships ~30 hard-coded English literals across [tray.rs](../../crates/tisvlay-tray/src/tray.rs) and [main.rs](../../crates/tisvlay-tray/src/main.rs) — menu items ("Settings", "Reload", "Quit", "Power Off", …), tooltip strings ("Daemon not available", "TisVlay [X/Y]"), volume/backlight labels, and error context. None of them route through gettext.

By comparison, [tisvlay-gui](../../crates/tisvlay-gui/Cargo.toml) has the full pipeline wired (see "Internationalization (i18n)" in [.claude/CLAUDE.md](../../.claude/CLAUDE.md)): `slint::init_translations!`, `gettext-rs` for Rust-side strings, a committed [tisvlay-gui.pot](../../crates/tisvlay-gui/lang/tisvlay-gui.pot) template, and `just i18n-{extract,update}` recipes.

The tray is the most user-visible surface after the GUI — it appears unsolicited in every desktop session — and shipping it monolingual when the GUI is translation-ready is a gap worth closing now while the string set is small.

Among the Rust i18n alternatives (Fluent via `fluent-rs`, `i18n-embed`, `rust-i18n`), `gettext-rs` is the right pick here:

- The GUI already uses it. Shared `.po`/`.pot` workflow means one translator tool (Poedit / Weblate / Lokalize) covers both crates.
- Slint chose gettext for `.slint` files (see [the Slint blog post](https://slint.dev/blog/translation-infrastructure) and slint-ui/slint#33), so the GUI is locked in. Forking the tray onto a different runtime would only pay off if the tray's string complexity (plurals, gender, message references, attributes) outgrew gettext — which it won't at ~30 strings.
- `slint::SlintContext::set_external_translator` (LibrePCB's PR #10979 against slint-ui/slint) keeps the door open: if the workspace ever wants Fluent end-to-end, both crates can move together without `.slint` source changes. No lock-in created by adopting gettext-rs now.

## Scope

In:

1. Add `gettext-rs = "0.7"` to [crates/tisvlay-tray/Cargo.toml](../../crates/tisvlay-tray/Cargo.toml), matching the GUI's pin. Add the `package.metadata.cargo-machete` ignore entry — the crate's Rust import alias drops the dash and machete doesn't reconcile.
2. New `crates/tisvlay-tray/build.rs` that walks `crates/tisvlay-tray/lang/*/LC_MESSAGES/*.po` and shells out to `msgfmt` to emit sibling `.mo` files, with `cargo:rerun-if-changed=` on each input. Mirrors what `slint_build` does invisibly for the GUI. Failure mode mirrors the GUI's `cargo-about` fallback: `cargo:warning=` if `msgfmt` isn't installed, skip the file (runtime falls back to the literal source string).
3. Init in [crates/tisvlay-tray/src/main.rs](../../crates/tisvlay-tray/src/main.rs) — explicit `bindtextdomain("tisvlay-tray", <lang dir>)` + `textdomain("tisvlay-tray")` + `setlocale(LC_ALL, "")`. Lookup-dir resolution mirrors the GUI's pattern: `CARGO_MANIFEST_DIR/lang` baked at compile time for dev runs out of the source tree, with the system `/usr/share/locale` path as the production fallback.
4. Wrap user-facing literals with `gettext()` across [tray.rs](../../crates/tisvlay-tray/src/tray.rs) and [main.rs](../../crates/tisvlay-tray/src/main.rs). Inventory below.
5. Refactor the half-dozen `format!("Label: {}", value)` sites to the GUI's idiom: `gettext("Label: {0}").replace("{0}", &value.to_string())`. xgettext can't extract from `format!()` — the literal must remain a bare string argument to a recognized keyword call.
6. Use `ngettext` for the count-bearing strings ("No TVs configured", "TisVlay [X/Y]"). The GUI's xgettext recipe already declares `--keyword=ngettext:1,2`; the tray would be the first call site in the workspace.
7. New `crates/tisvlay-tray/lang/tisvlay-tray.pot` (committed, generated by `just i18n-extract-tray`). Per-locale `.po` files land under `<lang>/LC_MESSAGES/tisvlay-tray.po` as translators contribute them; none ship in v1.
8. Extend the [justfile](../../justfile) `i18n-extract` / `i18n-update` recipes to cover both crates. Lean toward sibling recipes (`i18n-extract-gui` + `i18n-extract-tray`) plus an aggregator `i18n-extract` that depends on both — matches the workspace style of inlining commands rather than helper-factoring (see Design).
9. Update [.claude/CLAUDE.md](../../.claude/CLAUDE.md) — add tray to the "Internationalization (i18n)" section, note vendor backend strings remain out of scope.

Out:

- **Translating vendor-backend strings** (input names, profile names pushed from `tisvlay-lg`). CLAUDE.md already files this as "will eventually ship per-vendor `.mo` files" — the tray wraps its own surrounding labels ("Input", "Profiles") only.
- **Per-locale .po files.** v1 ships English-only for the tray, matching the GUI's current state.
- **Switching the tray to `i18n-embed` / `fluent-rs` / any other Rust i18n framework.** Considered and rejected; see Alternatives.
- **Live locale switching** (relocalize on the fly when the user changes system locale). Both crates restart-to-apply today; symmetry preserved.
- **Replacing the GUI's gettext pipeline with anything else.** Out of scope for this plan.

## Design

### Why a build.rs vs. checking in `.mo` files

The GUI gets `.mo` compilation for free from `slint_build::compile("ui/main.slint")` — Slint's `gettext` feature config triggers `msgfmt` as a side effect. The tray has no Slint dependency, so something else has to run `msgfmt`.

Two viable approaches:

- **`build.rs` + `msgfmt`.** Idiomatic Cargo pattern, `.mo` regenerates automatically on `.po` change, `target/`-only artifact, no churn in `git status`. Cost: a build-script shell-out to a system tool (`gettext` provides `msgfmt`, already in the Nix dev shell).
- **Check in `.mo` alongside `.po`.** Zero build complexity, runtime can `include_bytes!` directly. Cost: every `.po` edit produces two diffs; binary blobs in `git`; translators have to remember to recompile or wire a pre-commit hook.

Picking `build.rs` matches the GUI's transparent-compilation behavior and keeps the working tree clean. Failure mode mirrors the GUI's `cargo-about` pattern in [crates/tisvlay-gui/build.rs](../../crates/tisvlay-gui/build.rs): `cargo:warning=` and degrade rather than fail the build.

### Init timing and lookup-dir resolution

In `tisvlay-gui`, [src/lib.rs:228-237](../../crates/tisvlay-gui/src/lib.rs#L228-L237) calls `slint::init_translations!` very early in `run()`, before any user-facing strings are produced. The tray's analogue lands in [main.rs](../../crates/tisvlay-tray/src/main.rs) immediately after `tracing` init, before `DaemonClient::connect` — so startup errors that surface to the user also localize.

`gettextrs::TextDomain::new("tisvlay-tray").init()` is the higher-level API but its lookup logic isn't quite what we need: it walks XDG paths only, so dev runs out of the source tree miss the `lang/` directory. Falling back to the lower-level `bindtextdomain` + `textdomain` pair (the same primitives `init_translations!` calls under the hood) lets us point at `CARGO_MANIFEST_DIR/lang` in dev and let the system loader take over in installed builds. Pattern under exploration:

```rust
let lang_dir = std::env::var("TISVLAY_TRAY_LANG_DIR")
    .unwrap_or_else(|_| concat!(env!("CARGO_MANIFEST_DIR"), "/lang").to_string());
gettextrs::setlocale(gettextrs::LocaleCategory::LcAll, "");
gettextrs::bindtextdomain("tisvlay-tray", lang_dir)?;
gettextrs::textdomain("tisvlay-tray")?;
```

The env-var override is a development convenience for running the binary out of `target/debug/` against an alternate catalog directory; production paths ignore it. Confirm the exact shape against what slint's `init_translations!` macro expands to so the two crates resolve catalogs identically.

### Justfile shape

Lean toward sibling recipes plus an aggregator:

```just
i18n-extract: i18n-extract-gui i18n-extract-tray
i18n-extract-gui:
    # current contents of `i18n-extract`, renamed.
i18n-extract-tray:
    # Rust-only — no slint-tr-extractor pass.
    xgettext --language=Rust --keyword=gettext --keyword=ngettext:1,2 \
        --from-code=UTF-8 --package-name=tisvlay-tray \
        --copyright-holder='TisVlay contributors' \
        --output={{ tray_pot }} \
        $(find crates/tisvlay-tray/src -name '*.rs')

i18n-update: i18n-extract
    # loop over both crates' lang/ trees.
```

More verbose than a parameterized loop but easier to grep ("where does the tray's extract live?") and matches the workspace's existing inline-everything style.

### String inventory (approximate)

To be exact during implementation. Sourced from `grep '"[A-Z][a-z]' crates/tisvlay-tray/src/*.rs`:

- **Menu labels** (~17): `"Settings"`, `"Reload"`, `"Quit"`, `"Power Off"`, `"Power On (Wake)"`, `"Backlight Up (+10)"`, `"Backlight Down (-10)"`, `"Screen Off"`, `"Screen On"`, `"Volume Up (+10)"`, `"Volume Down (-10)"`, `"Mute"`, `"Unmute"`, `"Manage"`, `"Unmanage"`, `"Profiles"`, `"Input"`.
- **Submenu format strings** (~4, the `format!` refactor cases): `"Backlight: {0}"`, `"Volume: {0}{1}"` (where `{1}` is `" (muted)"` — also translatable), `"User: {0}"`, `"System: {0}"`.
- **Tooltip + title** (~8): `"TisVlay [daemon offline]"`, `"TisVlay [{0}/{1}]"` (ngettext-eligible), `"Daemon not available"`, `"No TVs configured"`, `"Daemon unavailable"`, plus the per-TV tooltip fragments `"\n  off"`, `"\n{0} volume {1}{2}"`, `"\n{0} backlight {1}"`.
- **`main.rs` error context** (~6, 2 borderline): `"Failed to create daemon client"`, `"Failed to spawn tray icon (is a StatusNotifierHost running?)"`, `"Failed to register tray D-Bus interface"`, `"Connect to session bus"`, `"Build org.freedesktop.Application proxy"`, `"Call org.freedesktop.Application.Activate"`. Plus `"Failed to register SIGTERM"` / `"Failed to register SIGINT"` — these only surface in panic messages, judgement call whether to translate.

Total: ~35 extracted, ~30 user-visible after dropping the panic-only literals.

### Don't translate

Per CLAUDE.md conventions:

- **Brand**: `"TisVlay"` — keep the literal in place even inside composite templates. For `"TisVlay [{0}/{1}]"`, accept that the brand text is part of the translatable string and translators leave it untouched.
- **Icon names**: `"video-display"`, `"video-display-symbolic"`, `"system-shutdown"`, `"view-refresh"`, `"application-exit"`, `"view-hidden"`, `"view-visible"` — freedesktop identifiers, never user-visible.
- **Glyphs**: `"►"` (active-scroll-target marker).
- **Identifiers**: profile/input/TV-ID strings flowing through from the daemon. These are either machine identifiers or human-readable names the user typed themselves; translating either is wrong.

### Test surface

- `crates/tisvlay-tray/lang/tisvlay-tray.pot` shape-checked by visual review of the first `just i18n-extract-tray` output.
- Coverage doesn't move — `gettext()` is transparent in the absence of a matching catalog. The `tisvlay-test` / `tisvlay-mock` / `tisvlay-harness` layers don't need to know about i18n.
- No new integration tests. The build-script failure path (missing `msgfmt`) is the same shape as the GUI's missing-`cargo-about` path and exercised by the same dev-shell-vs-bare-cargo split.

## Alternatives

### `fluent-rs` (rejected)

Mozilla's Fluent has real ergonomic wins over gettext for translator-visible features: locale-correct plurals via `intl_pluralrules`, message references and terms, attributes (one ID carries `.label` / `.tooltip` / `.aria-label` as a unit), BiDi isolation by default, non-fatal error handling, runtime catalog reload. Rejected because:

- The tray has ~30 strings — Fluent's selector/attribute power doesn't pay back at that scale.
- **No extractor exists** in the Fluent ecosystem; you hand-write `.ftl` and keep IDs in sync with code yourself. This re-introduces the workflow split with the GUI (which gets free extraction via `slint-tr-extractor` + `xgettext`).
- Translator-tool support is weaker (Pontoon strong, Poedit/Weblate/Crowdin weak or missing).
- `fluent-fallback`'s own README warns the API is *"in the early stages"* and asks consumers to *"work through the challenge of setting up the boiler-plate that will eventually go away."*
- `slint::SlintContext::set_external_translator` preserves a future migration path. The .slint authoring surface stays gettext-shaped, but both crates' runtime resolvers could switch together. No lock-in.

### `i18n-embed` with the gettext backend (rejected)

Thin framework wrapper that uses `RustEmbed` to bundle `.mo` files into the binary at build time, plus an `i18n.toml` config that automates `msgmerge`/`msgfmt`. Same `.po`/`.pot` source files; different runtime loader.

Rejected because:

- It would diverge the tray (`i18n-embed`-wrapped) from the GUI (`gettext-rs` raw) — the symmetry argument we're choosing gettext-rs for in the first place.
- The build-script complexity it eliminates (`msgfmt` shell-out) is ~15 lines.
- Modestly maintained — last meaningful release Nov 2023.

Revisit only if/when both crates want compile-time-embedded `.mo` files rather than system-installed.

### `rust-i18n` (rejected)

YAML/JSON catalogs, no proper plural rules, no `msgctxt` equivalent. Closer to a toy than a serious i18n stack. Not considered further.

### Check in `.mo` files alongside `.po` (rejected)

See ## Design / Why a build.rs vs. checking in `.mo` files.

### Reuse `slint::init_translations!` in the tray (rejected)

The macro pulls in the entire Slint runtime. The tray doesn't link Slint and has no plan to. Calling `gettextrs::bindtextdomain` directly is the same primitive without the dependency drag.
