# One way to mirror a service

Every client keeps a mirror of a service's cached keys and follows the service's lifetime through its liveliness token. Each mirror implements that by hand today, and three bugs found during the TV-controls-the-PC campaign (2026-10-25) were the same mistakes made in different copies. This plan gives the SDK one lifetime-scoped mirror primitive, builds every SDK client and the tray on it, fixes the services' own mirrors of each other, and tests them all against one harness that can cut a link. It runs as its own campaign after #216 and #217.

## The bugs, and the copies they came from

| Bug | Fixed in | The copy | The mistake |
|---|---|---|---|
| After the PC woke, the GUI's TV list and system profiles stayed empty | `606b35cb` (#216) | the SDK's daemon mirror (`DaemonClient`) | It took a vanished token for a stopped daemon and retired its session, so it ignored the same, still-running daemon once the token returned |
| After the PC woke, the tray showed the TVs without names | `280b450c` (#216) | the tray's own mirror | Subscribed once at startup, so the same daemon's history never replayed, and live samples recreated rows without their identity |
| The tray showed an extra, nameless TV | `b371f514` (#216) | the tray's own mirror | Made a TV row from a session-side assignment for a TV the daemon doesn't have |

Why the PC waking matters: systemd freezes `user.slice` around a sleep, and zenoh's 10 s link lease keeps counting through the kernel's device suspend and resume. A long wake therefore expires every user-side link, and each service's tokens disappear and return under the same zenoh session ([architecture.md](../architecture.md), empirical zenoh laws).

The mechanism behind bug 2, and behind the new findings below: an `AdvancedSubscriber` keeps each publisher's last delivered sequence number (for `RecoveryConfig`'s retention period, 1 h by default), and drops a replayed sample at or below it. When a publisher's token returns, `detect_late_publishers` queries its cache again, so a value that changed in the gap arrives, but an unchanged one is dropped. A subscriber that kept its state loses only deletes made in the gap; one that cleared on loss also loses every unchanged value, until it re-subscribes.

## What exists today

- **Three SDK mirrors** in `crates/tisvlay/src/{lib,mirror}.rs`, each with its own subscriptions, liveliness task and release check (`Handshake`, one per service, each with its own info rpc):
  - `DaemonClient` / `SystemMirror`: TVs and system profiles, `tisvlay/<site>/tv/**` and `profile/system/*`. Since #216 it subscribes per token lifetime (`mirror_daemon`), clears on loss, subscribes before it reports the daemon available, and aborts a lifetime's started tasks when a later subscribe fails. If a subscribe fails, the daemon still reads as available and nothing retries until the next liveliness sample.
  - `SessionClient` / `UserMirror`: user profiles, assignments and the stream state, `tisvlay/<site>/user/**`. It subscribes once and never acts on the session's token going away.
  - `TrayClient` / `TrayMirror`: the notification settings. It subscribes once and keeps the settings while the tray is down, a promise the published README makes (`crates/tisvlay/README.md`, "kept while it's down"). Only the GUI reads it; the tray's own notifier reads its file.
- **A fourth mirror in the tray**, which uses the SDK only in its tests: `crates/tisvlay-tray/src/state.rs` (`Mirror`, `TvView`) and the pumps in `lib.rs`. Its daemon subscriptions follow the token (its own `mirror_daemon`); its user-socket subscription doesn't. Its toasts use plain live subscribers on purpose, so a restart doesn't replay finished pairings.
- **Blank rows in the SDK:** `SystemMirror::apply` creates a TV row for any `tv/**` key (`mirror.rs`, `entry(tv).or_default()`), so a `progress/power` sample, or a live sample arriving before identity, makes a nameless TV. This is bug 2's mistake inside the SDK.
- **The services' mirrors of each other:**
  - The daemon's stream mirror (`crates/tisvlay-daemon/src/lib.rs`, the `stream_state` subscriber) keeps one subscriber and sends an empty armed set when the session's `session_alive` token goes away. When the same session's token returns after the PC wakes, its unchanged stream sample is dropped as already delivered, so `while_streaming` TVs likely stay disarmed until the stream state next changes.
  - The session's fleet and screen mirrors (`tv/*/meta/config`, per-TV power) subscribe once. They don't clear, so they lose only a TV removed while the session's system link was down. The session talks to the daemon through a raw `Caller` and never checks the daemon's release.
- **Deletes in a gap:** a profile or assignment deleted while the session service is down, or while the client's link is down, stays in `SessionClient`'s mirror, since the delete isn't replayed. The GUI shows user profiles from this mirror.
- **Recovery:** every service's publishers have a one-sample cache and send a miss-detection heartbeat every 500 ms, whether or not anything changed (`bridge.rs`, the session's publishers, the tray's `notify.rs`). Only the CLI's `watch` enables recovery (`RecoveryConfig::default().heartbeat()`); the SDK and tray mirrors don't, so a put lost within a lifetime is never retransmitted to them. A delete is sent through its publisher, which is then dropped with its cache and heartbeat, so a lost delete can't be recovered at all.
- **The GUI** drives its profile editor's cache and selection from `*Removed` events only, does nothing on `*Disappeared`, and shows "No TVs configured" between `DaemonAppeared` (sent once the subscriptions are declared) and the first history sample.
- **zenoh 1.10.1** is locked (`Cargo.toml` allows `1.10` and `~1.10`).

## zenoh 1.10.2

Released 2026-10-28. Its zenoh-ext sources are unchanged from 1.10.1, so the APIs and recovery semantics this plan relies on stand. The bump is lockfile-only (the 21 zenoh crates, and `dirs` drops out); zenoh's Rust 1.75 pins live in its own lockfile and don't reach ours. Two of its fixes bear on this plan:

- **Undeclared publishers and later puts** (eclipse-zenoh/zenoh#2832). When a publisher was undeclared, its session kept trusting a subscriber list for that key that its hub no longer updated, so later puts on the key were dropped once the key's subscribers changed. The fix covers the peer hat (the daemon) and the client hat (the session's system link, the tray's settings link). This plan's pattern hits both conditions: the services delete a key and drop its publisher, a record can come back under the same key (a system profile re-created under its name), and every mirror now re-subscribes per lifetime, changing the subscribers. The bump lands first, and the harness gets a case for it.
- **Unresponsive transports fail fast** (eclipse-zenoh/zenoh#2709). A push that can't complete within `wait_before_close` closes the transport, but until 1.10.2 every later push blocked for the same period again. With RX workers holding routing locks, that could stall the whole session. A frozen `user.slice` before a sleep is such a peer: the process doesn't close its socket, it just stops reading. The harness models it with a stall mode, besides the cut.

One fix on zenoh's main, not yet released, matters to the harness: #2897 stops pending connects from holding a session's close until `open_timeout`. Until a release carries it, the relay refuses new connections while it's stalled or cut, rather than accepting and never answering, so test teardown doesn't wait 10 s per client.

## Decisions (2026-10-31)

1. **The shape: a `Mirror` trait driven by a generic `LifetimeMirror<M>`.** The precedent is tokio-util's `FramedRead<T, D: Decoder>`: a generic driver owns the I/O, and a trait carries the stateful per-item logic. The mirror types (`SystemMirror`, `UserMirror`, `TrayMirror`) implement `Mirror`; `LifetimeMirror` is the driver that follows one service's lifetime.
   - **The trait:** `const SERVICE: Service`, `fn keys(site) -> Vec<String>` (the key expressions to subscribe), `fn apply(&mut self, site, &Sample) -> Option<StateEvent>`, and `fn clear(&mut self, site) -> Vec<StateEvent>` (an event per row that was showing). No associated event type: every event goes out on the one `broadcast::Sender<StateEvent>` that `StateWatcher` merges.
   - **The driver:** `LifetimeMirror::start` derives the liveliness key, the info rpc and the Appeared/Disappeared events from `M::SERVICE`. It owns the liveliness subscriber, the per-lifetime subscriptions, the availability flag (today's `daemon_alive` and siblings), the hydrating state (decision 5), and an `Arc<Handshake>` it exposes for `StateWatcher`, `refuse_known_mismatch` and the progress streams. It is `Clone` (an `Arc` inside), with `M: Send + 'static`.
   - **Ordering:** on loss it aborts, then awaits, each of the lifetime's tasks, and only then calls `clear`, so an in-flight `apply` can't bring back state after the clear. The mirror stays behind a std `Mutex`, never held across an `.await`.
   - **Failure:** a failed subscribe retries with a capped backoff while the token is present; the service reads as available only once every subscription is declared.
   - **Visibility:** both are `pub(crate)`. Third parties use the clients; a public trait over `zenoh::Sample` would freeze its shape under semver. The SDK is the home rather than `tisvlay-runtime`, since a published crate can't depend on an unpublished one.
   - **Why a lifetime layer of our own:** zenoh-ext's `AdvancedSubscriber` detects late publishers and recovers misses per publisher, but has no notion of a service going away, and its sequencing drops history it has already delivered. A mirror that clears on loss must therefore re-subscribe on return to get the history again, which is the `DaemonClient` pattern.
2. **Recovery, with sporadic heartbeats.** The primitive's subscriptions enable `RecoveryConfig::default().heartbeat()`, which works against all three services' publishers. The publishers switch to `sporadic_heartbeat`, which sends only in a period after a change, so recovery doesn't cost every client about 2 Hz per key. A delete lost within a lifetime converges at the next lifetime; the harness's lost-sample case is a put.
3. **Every mirror clears while its service is down,** uniformly: the daemon's, the session's and the tray settings'. Clients show the service as offline rather than stale state that edits would fail against. This retires the tray settings' "kept while it's down" and changes the meaning of `SessionDisappeared` and `TrayDisappeared` in the published SDK.
4. **Rows come from the service that owns them, and only once their identity has arrived.** TVs come from the daemon; another service's data is a lookup (the SDK's `UserMirror.assignments` already is), and a lookup that misses renders as unassigned, not as an error. Within one service, a TV row exists only once its `meta/identity` has arrived; other keys update a hidden partial row. The primitive can't enforce either, so it's a written rule for mirror types in architecture.md and two conformance cases.
5. **A hydrating state, ended by a row count.** Between a service's token appearing and its history arriving, a client reports the service as hydrating, and the GUI shows "Loading" rather than "No TVs configured" or an empty profile list. zenoh-ext exposes no "history done" signal (its initial-replies handler is private), so each service's info reply carries its row count: the client is hydrated once its mirror holds that many rows, or after a short fallback timeout, since rows can change between the reply and the history. The info call already runs once per lifetime for the release check. This is a wire change, so a `feat`.
6. **The services' mirrors of each other are fixed in this campaign.**
   - **The session goes onto the SDK.** The session predates the SDK and never adopted it; nothing structural keeps it off. Its system link holds a `DaemonClient` built on that existing session, which replaces its fleet and screen mirrors (`tv/*/meta/config`, per-TV power) and its raw `Caller` for rpcs to the daemon. Any client method the session's dispatch needs and the SDK lacks lands in the same commit. Its live-only subscribers (the TV powering off, the remote's power key) stay raw: they keep no state.
   - **The session is release-gated,** like every client. Against a daemon of another `major.minor` (an upgrade without a re-login), it stops dispatching power actions until the user logs in again, and logs the mismatch; the tray's mismatch item and toast (decision 7) tell the user. Today it carries on blindly.
   - **The daemon's stream mirror is fixed by hand,** at its one site: it re-subscribes `stream/state` when the session's `alive/session` token returns. No SDK client can serve it, because the daemon never sees the user socket, only the session's system-link presence. Being the only service-to-service mirror left, it's not a copy.
7. **The tray moves onto the SDK in this campaign,** as its last step. The tray builds its menu from `DaemonClient`, `SessionClient` and the `StateWatcher` event stream, and `state.rs`'s mirror and the tray's pumps go. It undoes two documented choices, on purpose:
   - **Version-gated:** the tray goes through the clients, so a release mismatch gates it like the GUI (architecture.md § Compatibility says today it goes "through `Caller` directly" to avoid that). The menu shows a single disabled item instead of TVs, naming both releases and saying to log out and back in, and one notification fires when the mismatch is first seen.
   - **One link per socket:** the clients' constructors over a caller-provided zenoh session (landed with the session's move, decision 6) let the tray keep its connect-only system link and its supervised user-socket link (architecture.md § Process inventory), and its commands move from raw `Caller`s to the client methods.
   - **SDK additions,** landing in the same commit as their first use: `Option` volume, backlight, mute and input on `TvInfo` (`#[non_exhaustive]`; a 0 would seed the scroll reconciler), live-only all-TV pairing and power-progress streams yielding the TV id, and connection-transition toasts computed tray-side by comparing against the TVs last seen (a TV seen for the first time, or re-hydrated after a clear, is not a transition).

## Implementation

One linear campaign branch, a commit per step. Each step updates the docs it makes stale.

- [x] **0. zenoh 1.10.2** (`fix(deps)`). `cargo update -p zenoh -p zenoh-ext`; the full test suite passes on it before anything builds on it.
- [x] **1. The harness, failing cases ignored** (`test(sdk)`). A Unix-socket relay in `tisvlay-test` that a test can cut (closing the link while the service keeps its zenoh session, the way a lease expiring after the PC wakes does), stall (stop forwarding without closing, the way a frozen `user.slice` does, then cut once a short test lease would have expired), and use to drop one frame (a lost sample). While stalled or cut, it refuses new connections. The fake service extends the SDK tests' `stub_service!` into a helper module; the SDK's tests move to `tests/it/{main,client,conformance}.rs`. Cases: a link cut and restored under the same session, a link stalled then cut, a restart under a new one, a record deleted and re-created under the same key before a client re-subscribes (zenoh#2832), a record deleted while down, a put lost within a lifetime, a non-identity key arriving before identity, an assignment for a TV the daemon doesn't have, and the services' mirrors across a cut (the daemon's stream mirror against the real `serve`). Cases the code fails today are `#[ignore = "…"]`, and the step that fixes each turns it on. The real-daemon restart test (`daemon_restart_discards_previous_lifetime_tvs_and_profiles`) stays as it is. Docs: `.claude/CLAUDE.md` and `docs/testing.md` on the SDK's test layout and the relay.
- [x] **2. The primitive, with `DaemonClient` on it** (`fix(sdk)`: identity-gated rows, subscribe retry, recovery). `Mirror` and `LifetimeMirror<M>`; `SystemMirror` implements `Mirror` and creates rows only from identity; `DaemonClient` keeps its public surface, and its liveliness task and `mirror_daemon` go. Recovery is on from the start. The daemon cases turn on, and the SDK's `a_daemon_whose_token_returns_is_mirrored_again` folds into them. Docs: a new `## Clients` section in architecture.md, after § Compatibility, as the one canonical home for the primitive, the identity rule and the join rule; the empirical-law entry on link drops shrinks to a clause plus a link, and `.claude/CLAUDE.md`'s copy likewise.

## Out of scope

- The CLI's `watch`: it streams samples and keeps no mirror.
- The greeter's `greeter_timeout` subscriber: a single live value, no rows.
- Whether to lengthen zenoh's 10 s lease on the Unix-socket links, so the PC waking doesn't drop them at all: an open decision, filed in [docs/ideas/](../ideas/README.md) when this plan retires. With this plan, a drop is harmless either way.
